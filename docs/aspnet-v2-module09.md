Девятый модуль добавлен по девяти файлам уроков, контрольному тесту и ключу. Оригиналы без изменений находятся в `server/theory-source/aspnet-core-v2-module09/`. Курс `aspnet-core-foundations-v2` v60, каталог revision 235.

Девять уроков содержат 18 мини-проверок, 45 итоговых вопросов уроков и 20 контрольных — всего 83 с пояснениями. Пять интерактивов размещены по одному в уроках 1, 3, 5, 6 и 9: границы Data Annotations, атомарность бизнес-инвариантов, сборка ValidationProblem, подключение ExceptionHandlerMiddleware и негативные HTTP-сценарии. Дополнительные уроки не создавались.

Доступны девять модулей из 27: 80 уроков, 45 интерактивов, 160 мини-проверок и 580 вопросов на оценку. Модули 10–27 показывают «Скоро появится». Первые восемь модулей и их размещения упражнений сохранены; курс C# и его sidecar сверены по SHA-256. Авторские ключи и источники не выводятся в ученической теории.

## Коррекция примеров при импорте

В уроках 5, 6 и 8 у throw-only expression lambdas в MapGet добавлен явный возвращаемый тип IResult: `IResult () => throw ...`. Без него компилятор не может выбрать подходящую перегрузку MapGet (CS1593). Исходные Markdown остаются неизменными. Проверка сохранности code fences учитывает только эту коррекцию.

## Проверки

- 410 автоматических тестов и семь API-проверок проходят. Веб-сборка успешна. Lint содержит восемь прежних предупреждений; сборщик предупреждает о размере основного JS-файла.
- `scripts/check-aspnet-v2-module09.mjs` проверяет MVC/Minimal API validation, пользовательский атрибут, отдельный request DTO, IValidatableObject, ограничения длительности, чистые TransferRules, отображение доменных ошибок, Problem Details, fallback IExceptionHandler и настройку диагностики, различия route/binding, конфликт и безопасный 500 с разными Accept. Проверяются эталон сборки ValidationProblem и все четыре варианта задания middleware.
- Для неверного UseCors без AddCors ожидается отказ запуска при активации CorsMiddleware без требуемых регистраций; это отдельная отрицательная проверка, а не HTTP 500. Для неверных UseStatusCodePages/UseRouting ожидается 500 вместо требуемого 503. Пользовательский код в приложении не выполняется.
- Фрагменты собираются в тестовом MVC-проекте с нужными DTO, using и регистрациями из контекста. Пример EF Core атомарного UPDATE, фрагменты xUnit/WebApplicationFactory и конфигурация реальной аутентификации не выдаются за проверенные интеграции с PostgreSQL/Identity. Для них здесь сохранён учебный контекст; БД и production-схема доступа не развёртывались.
- На ширине 390 px проверены правильные/неправильные решения всех пяти заданий, восстановление после перезагрузки и сброс рабочего ответа. Сброс сохраняет ранее полученную отметку успешного выполнения согласно существующему поведению. Консоль без ошибок, горизонтального переполнения нет.
