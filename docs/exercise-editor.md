# Визуальный редактор интерактивных упражнений — этап 7А

Редактор работает в существующем React-приложении и сохраняет данные через существующий ASP.NET Core Content API. Это **локальный инструмент управления контентом**, а не новый аккаунт ученика и не удалённая CMS. Через его API опубликованы партии 7Б.1, 7Б.2 и 7Б.3: всего 49 упражнений во всех 19 модулях, [актуальное покрытие курса](csharp-interactive-coverage.md).

Через тот же API опубликовано дополнение из 13 заданий: сейчас **62**, минимум три в каждом модуле, курс v70 / каталог 79. Все прежние 49 сохранены. [Протокол публикации и проверок](csharp-batch04-verification.md).

Актуальное дополнение: **96** заданий, минимум пять на модуль и максимум одно в уроке. Тем же save/publish выполнены десять переносов с прежними версиями упражнений и опубликованы 34 новых. Курс v114, каталог 123. [Текущий протокол](csharp-batch05-verification.md).

## Запуск и доступ

1. В корне проекта запустите `npm run authoring:dev`. Нужны Node.js 24 и .NET SDK 10; они уже доступны на этом компьютере.
2. Запустите обычный Vite: `npm run dev -- --host 127.0.0.1 --port 5193 --strictPort`.
3. Откройте `http://127.0.0.1:5193/#/authoring`. В dev-версии есть ссылка «Управление контентом → Интерактивные упражнения» в личном кабинете.
4. Вставьте ключ из `.tools/authoring-token.txt`. Скрипт первого запуска создаёт случайный 256-битный ключ; значение не выводится в терминал и не включается в клиентскую сборку.

Во время выполнения задачи API и сайт оставлены запущенными на 5129 и 5193. После перезапуска компьютера снова выполните команды выше. На Windows Node.js расположен в `C:\MyApps\Nodejs`; при необходимости используйте npm.cmd и добавьте эту папку в PATH текущего терминала.

Ключ хранится в игнорируемой папке .tools и только в памяти открытого редактора. После обновления страницы требуется повторный ввод. Чтобы заменить ключ, остановите сервер, замените содержимое файла случайной строкой не короче 32 символов и запустите снова. Не загружайте .tools на хостинг и не отправляйте ключ ученикам.

## Права на сервере

В проекте нет регистрации, ролей и существующей административной панели. Поэтому роль управляющего контентом задаётся локальным bearer-ключом. GET и POST `/api/authoring` защищены на сервере, а не только в интерфейсе:

- требуется Development и Authoring:Enabled=true;
- запрос должен прийти с loopback-адреса;
- ключ сравнивается через постоянное время по SHA-256;
- браузерные Origin разрешены только для localhost/127.0.0.1/::1;
- ответы не кешируются, cookies не используются;
- в Production редактор возвращает 404 даже с верным ключом и флагом Enabled;
- обычные `/api/catalog` и `/api/courses/...` остаются доступными для чтения;
- приватные черновики не публикуются как статические файлы.

Скрипт запуска привязывает сервер только к 127.0.0.1:5129. Не превращайте этот dev-инструмент в удалённую админку через изменение bind-адреса: для совместной работы через интернет нужны полноценная авторизация, роли и развёртывание. Настройки сервера имеют имена Authoring__Enabled, Authoring__Token и Authoring__Node; секрет не должен иметь префикс VITE_.

## Общий рабочий процесс

Выберите тип в «Тип нового упражнения» → «Создать упражнение». Заполните название, описание, инструкцию, необязательную сложность, сообщения проверки и объяснение. ID генерируется автоматически и остаётся стабильным. Тип существующего упражнения не меняется; для другого типа создайте новое.

Затем выберите курс, модуль, урок и позицию. Доступны позиции после каждого обычного блока — не только после теории, но и после промежуточной проверки. Последний блок дополнительно подписан «перед итоговым тестом». Первым блоком урока остаётся теория. Несколько упражнений могут стоять на одном якоре; опубликованный порядок меняется ↑/↓ в списке.

«Проверить данные» использует действующий validateExercise и специализированные валидаторы. Неисправное упражнение нельзя сохранить или опубликовать. Во время редактирования поля могут временно быть неполными; ошибки показываются до отправки, а сервер повторяет проверку. Несохранённые изменения защищены предупреждением при закрытии/переходе к другой форме.

«Сохранить черновик» записывает его на сервер. Ученик продолжает получать прежнюю опубликованную версию. «Предпросмотр» открывает настоящий ExercisePlayer: можно отвечать, проверять, повторять и сбрасывать упражнение. Общий учебный прогресс, серия и монеты не меняются. Опция 390px запускает тот же Player в отдельном iframe с собственным viewport, чтобы работали мобильные media queries и выпадающие списки.

«Опубликовать в уроке» доступна после сохранения текущей формы. Публикуются упражнение и его размещение, собирается курс и обновляется серверный каталог. После публикации задания доступны обычному ученику. Для клиента, уже поддерживающего все семь типов, новые материалы распространяются как обновление контента. Сам редактор предназначен для браузера разработки, APK в этапе 7А не собирался.

## Формы семи типов

### Сопоставление

Добавляйте/изменяйте элементы двух групп. Для каждого элемента первой группы выберите правильный элемент второй. Удаление элемента очищает затронутые ссылки; оставшиеся незаполненные пары необходимо исправить перед сохранением. ID назначаются автоматически, совпадения и неполные пары проверяются действующим движком. Лимит — 12 элементов в группе.

### Последовательность

Добавляйте текстовые шаги. В каждой правильной последовательности двигайте шаги через существующий OrderList с кнопками ↑/↓. Можно добавить несколько допустимых порядков. Добавление/удаление шага обновляет списки ID, не оставляя ссылок на удалённый элемент. Лимиты движка — 20 шагов и 20 допустимых порядков.

### Сборка кода

Задайте язык, многострочные фрагменты, контекст и фиксированные prefix/suffix. Порядок и альтернативы редактируются тем же OrderList. Собранная программа показана текстом непосредственно под формой; предпросмотр ученика использует настоящий code-order. Код нигде не компилируется и не исполняется.

### Найди и исправь ошибку

Введите код и нажмите одну непустую ошибочную строку в нумерованном представлении. Добавьте варианты исправления и отметьте правильные; задайте объяснение ошибки. Поддерживается ровно одна ошибка в соответствии с текущей моделью, но несколько допустимых исправлений. Номера за пределами кода и отсутствующие варианты отклоняются.

### Преобразование данных

Исходные числа, строки, boolean и плоские объекты редактируются таблицей. Для объектов можно добавлять/переименовывать поля и выбирать их типы. Разрешённые операции добавляются отдельно: Filter, Select, OrderBy, ThenBy, GroupBy, Count. Для каждой настраиваются поля, операторы, значения, режимы/направления.

Настройте лимит шагов, обязательные/запрещённые операции и сравнение порядка. Эталонная цепочка собирается через существующий DataTransformInput. Кнопка «Использовать результат эталона как цель» получает target через тот же декларативный движок. Простой target-list редактируется таблицей; сложные группы/результаты могут дополнительно вводиться JSON. Исходный каталог операций проверяется отдельно от эталонной цепочки, чтобы автор мог исправить решение, пока цель ещё меняется. Ограничения 100 строк и 12 шагов сохранены.

### Трассировка

Введите код; переключайтесь между initial и шагами, копируйте снимки, удаляйте и перемещайте их. Выбирайте подсвеченные строки кнопками. В каждом снимке задавайте переменные, объекты, ссылки, структурированные значения, вывод и объяснение. Поля имени/типа/области переменной синхронизируются по её стабильному ID между снимками; тип объекта также синхронизируется по ID. Можно вернуть переменную/объект из другого снимка, сохранив идентичность.

Редактор значений различает число, строку, boolean, null, ссылку, массив и запись. Для объекта редактируются поля записи. Панель вывода может отсутствовать, иметь пустой список либо содержать пустую строку — эти случаи сохранены.

Для любого непоследнего снимка можно создать предсказание: значение переменной, накопленный вывод, объект ссылки или описание следующего состояния. Настраиваются варианты, правильный вариант и объяснение. Правильные значения сверяются со следующим снимком тем же валидатором, что и в учебном режиме. Автоматической генерации шагов по исходному коду нет.

### Архитектурная схема

Создайте типы отношений, палитру, допустимые отношения каждого компонента, максимумы экземпляров и необязательные роли. Затем соберите эталон в существующем ArchitectureInput. Узлы и связи эталона обязательны; координаты не участвуют в проверке и не записываются в шаблон.

Добавляйте альтернативные схемы, разрешённые дополнительные компоненты/соединения, запрещённые компоненты/соединения и режим обратной связи. Семантические правила связей редактируются выбором типов и необязательных ролей концов. Устаревшие узлы/связи после изменения палитры можно удалить через текстовый список эталона, затем продолжить визуальную сборку. Применяется исходный ограниченный алгоритм сопоставления графов, второго алгоритма нет.

## Постоянное хранение и основной источник

- **Опубликованный источник**: `server/exercise-source/<courseId>.json` — прежний массив размещений `{moduleId,lessonId,afterBlockId,block:{id,kind:"exercise",exercise}}`.
- **Редактируемые копии**: `server/exercise-drafts/drafts.json`. Элемент содержит courseId, exercise, placement и baseFingerprint опубликованной версии. Это приватное рабочее состояние автора, не второй опубликованный каталог.
- **Собранные курсы**: `server/course-source/<courseId>.json`.
- **Раздаваемые версии**: `server/AnswerBook.ContentApi/content` с неизменяемыми payload-файлами и последней атомарно обновляемой catalog.json.

Обычный C#-импортёр по-прежнему читает тот же опубликованный sidecar. Поэтому последующий Markdown-импорт сохраняет редакторские упражнения и их порядок. В ходе задачи повторный импорт оставил версию курса 32, а все семь новых заданий — на местах. Черновики не участвуют в импорте и не появляются в курсе до публикации.

Сервер запускает фиксированный Node-валидатор scripts/authoring-command.mjs через ProcessStartInfo без shell. Он использует те же TypeScript-валидаторы, attachExercises и publishLearning, что и импортёр/клиент. Тип команды выбирается из разрешённых операций; пользователь не управляет исполняемым файлом, путём скрипта или файловыми путями. Произвольный код из JSON не выполняется. Общие движки читают код упражнений только как текст.

## Версии, конфликты и ошибки записи

Сохранение черновика не меняет опубликованный exercise.version, fingerprint или прогресс учеников. При публикации изменённого содержимого сервер назначает version+1. Изменение только размещения не меняет версию упражнения, но обновляет версию курса. Повторная публикация неизменённого содержимого не создаёт новую версию упражнения. Для любого опубликованного изменения сохраняются действующие правила восстановления прогресса: изменённое упражнение может начать новый проход, остальные сохраняются. Даже небольшая правка черновика ничего не сбрасывает до явной публикации.

Все операции имеют глобальную оптимистическую revision. Если источник/черновики изменились после открытия формы, сервер возвращает 409 и не перезаписывает данные. Основа формы хранится отдельно от обновляемого списка: нажатие «Обновить список» не делает устаревшую форму пригодной для перезаписи. Откройте актуальный черновик заново для сравнения, скопировав несохранённый текст при необходимости. Если опубликованный источник изменился вручную, baseFingerprint дополнительно блокирует публикацию старого черновика. Доступны «Открыть опубликованную версию» и дублирование с новым ID.

Общий межпроцессный lock используется редактором, импортёром и CLI-публикатором. Файлы заменяются через временный файл и rename. До публикации подготавливаются immutable payloads. Журнал в .tools сохраняет предыдущие значения и хеши целевых файлов; manifest обновляется последним. При следующей операции незавершённая транзакция откатывается, а полностью завершённая — подтверждается без отката версии. Чужая запись или ошибка диска не должна оставить половину опубликованного курса. При неопределённом результате сетевого запроса обновите список перед повтором.

Максимум 2 МБ в запросе, 100 упражнений в одном импорте, 1000 черновиков суммарным размером до 10 МБ. Работают прежние пределы каждого движка. Сервер заново валидирует хранилище и при чтении.

## Импорт, экспорт, дублирование и удаление

Экспорт одного упражнения — исходный Exercise без нового формата. Экспорт опубликованных — исходный массив размещений текущего импортёра. Импорт принимает Exercise, размещение или массив. Для Exercise без размещения используется выбранная позиция формы (или первая позиция первого курса).

Импорт повторяет серверную проверку, не выполняет частичного сохранения ошибочного массива и не перезаписывает существующие ID. Если требуется копия, отметьте «Импортировать как копии с новыми ID». Для редактирования существующего упражнения откройте его из списка. Дублирование создаёт новый ID, version=1 и неопубликованный черновик.

Удаление требует отдельного подтверждения. Оно удаляет выбранный черновик и, при наличии публикации, убирает упражнение из урока новой версией курса. Остальные задания, вопросы и прогресс не удаляются. Неизменяемые ранее разданные версии остаются для совместимости/истории; офлайн-устройство получит удаление после обновления каталога.

## Проверки и ограничения

Команды: `npm test`, `npm run lint`, `npm run build`; при запущенном авторском API — `npm run authoring:test:api`. На Windows sandbox может запрещать атомарное rename во временных каталогах: в ходе работы файловые тесты выполнены с разрешением на эту операцию.

Проверяются все семь типов, сохранение/публикация, копирование и удаление, размещение и порядок, черновики, импорт/экспорт, конфликт revision и опубликованной основы, ошибки диска, восстановление журнала, повторный импорт, изоляция предпросмотра и совместимость старых упражнений. API-проверки проверяют ключ, Origin, приватность черновиков, валидацию до записи, 409, публичное чтение и отключение Production.

Браузерная проверка: созданы семь опубликованных примеров, изменены поля специализированных форм, сопоставление успешно выполнено в настоящем предпросмотре. В узком iframe работал конструктор графов.
