## C# 14 / .NET 10

`node --experimental-strip-types scripts/check-csharp-batch03.mjs` — отдельный developer-only скрипт с фиксированными программами автора. Он не импортируется приложением и API, не принимает и не исполняет код ученика. SDK **10.0.400**, язык **14.0**, target **net10.0**: **33 из 33** случаев прошли.

- LINQ: вывод `2,3,4` / `2,3`; журнал вызовов предиката подтверждает отсутствие перечисления при создании Where, первое перечисление на ToArray и повторное при string.Join. Контрольная ранняя материализация даёт другой результат `2` / `2`.
- using: `open → body → dispose → catch → finally → after`. Контрольный using declaration во внешней области освобождается позднее; это другая структура, не альтернативный правильный ответ исходного задания. При провале конструктора Dispose не вызывается. Фильтры catch, ошибки конструктора/Dispose и финализаторы в условии исходного задания исключены.
- AAA: из установленного шаблона .NET 10 взяты реальные пакеты xUnit 2.9.3, Microsoft.NET.Test.Sdk 17.14.1, runner 3.1.4. В отдельном проекте выполнены оба допустимых порядка Assert — по одному успешному Fact. Намеренная ошибка SUT «вернуть false, но списать деньги» обнаружена xUnit через проверку баланса; ожидаемое падение подтверждено TRX. Это успешный отрицательный сценарий подготовки, не оставленный падающий тест приложения.
- Граничные тесты: для 17/18/65/66 подтверждены False/True/True/False. Четыре намеренно ошибочных сравнения показывают, какой именно вход обнаруживает дефект; случайный возраст из середины не заменяет границу.
- WhenAny: `10`, `False`, `20`. Завершение задано вручную TaskCompletionSource, таймеров нет. Отдельные случаи подтверждают успешное внешнее ожидание с ошибочной или отменённой Task-победителем и наблюдение ошибки/отмены на отдельном await winner.
- Гонка: два настоящих Thread с Barrier читают 0 до любой записи, затем управляемо пишут 1 и 1. Итог 1, инструментирование подтверждает обе локальные копии 0. Контрольная замена на Interlocked.Increment даёт 2. Упражнение явно выбирает T1-read первым; это не обещание единственного чередования произвольной программы. Управляющие сигналы нужны для демонстрации потерянного обновления, а не являются исправлением инкремента.
- SemaphoreSlim: успешная работа возвращает счётчик к 1; исключение внутри работы тоже возвращает разрешение. Уже отменённый токен при пустом или доступном семафоре не приводит к Release. Отмена во время реально незавершённого WaitAsync оставляет счётчик 0. Контрольное помещение WaitAsync внутрь ошибочного try/finally добавляет чужое разрешение (1 вместо 0), показывая причину отклонения такого порядка.
- GC: чистый обход заданного графа даёт достижимые A/B/C и кандидатов D/E. Настоящий GC не вызывается и его тайминг не тестируется. Статусы в ответе — классификация, а не дополнительные сильные ссылки в куче.
- Span: исходный массив `1,20,3,4`, копия `2,99`; дополнительно проверены смещение/длина. Попытка писать через ReadOnlySpan даёт CS8331, boxing Span — CS0029. В сценарии нет await и нарушения времени жизни ref struct.
- with: `old:new`, `1,2`, `False`, `True`. Явная копия вложенного списка в контрольном варианте даёт независимость: `old:new`, `1`, `False`, `False`.

Повторно пройдены **22** случая 7Б.1 и **53** случая 7Б.2. Всего **108** успешных SDK-проверок трёх партий, включая ожидаемые ошибки компиляции/исполнения и отрицательный тест SUT. Результаты и журналы — `artifacts/csharp-batch0N-sdk/`, `artifacts/csharp-batch0N-sdk-log.txt`; реальные xUnit/TRX — `artifacts/csharp-batch03-xunit/`.
