# ASP.NET Core — Слой данных и согласованность

Четырнадцатый модуль добавлен по восьми файлам уроков, контрольному тесту и ключу. Оригиналы без изменений находятся в `server/theory-source/aspnet-core-v2-module14/`. Курс `aspnet-core-foundations-v2` v91, каталог revision 261.

Восемь уроков содержат 16 мини-проверок, 40 итоговых вопросов уроков и 20 контрольных — всего 76 с пояснениями. Пять интерактивов размещены по одному в уроках 1, 3, 4, 6 и 7: Unit of Work, обязанности прикладного сервиса, сборка атомарного резервирования, сбои Outbox и исправление keyset-границы. Дополнительные уроки не создавались.

Доступны четырнадцать модулей из 27: 131 урок, 70 интерактивов, 262 мини-проверки и 935 вопросов на оценку. Модули 15–27 показывают «Скоро появится». Первые тринадцать модулей и их упражнения сохранены; курс C# и его sidecar сверены по SHA-256. Источники и авторские ключи не отображаются в ученической теории.

## Согласование с общей моделью

В endpoint урока 1 создание Product согласовано с обязательным Sku из модуля 11: поле добавлено в CreateProductRequest и явно присваивается из request.Sku. Константный SKU для всех запросов не вводился. Исходный Markdown не менялся; проверка code fences учитывает только эту адаптацию.

Пример InventoryService с чтением остатка и последующей записью сохранён как учебная демонстрация недостаточной защиты от гонки. В исходном уроке и вопросах прямо требуется понять эту проблему; он не выдаётся за атомарное решение.

## Проверки

- 430 автоматических тестов и семь API-проверок проходят. Веб-сборка успешна. Lint содержит прежние предупреждения; сборщик предупреждает о размере основного JS-файла.
- `scripts/check-aspnet-v2-module14.mjs`: девять успешных сценариев на .NET 10 и Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3. Компилируются endpoints, репозитории, application service, условный UPDATE, резервирование и Serializable-транзакция с необходимыми введёнными типами.
- DTO-проекция репозитория переводится в SQL без выборки Sku. Для preview терминальная SingleOrDefaultAsync заменена только в проверочном адаптере на ToQueryString; это не проверка исполнения SingleOrDefault.
- В Outbox-сценарии проверены состояния Added заказа и сообщения, AggregateId, версия EventType и сериализованный Id. Сохранение заменено обнаружением изменений в тестовом адаптере; подтверждается staging объектов, а не атомарность PostgreSQL или отправка брокеру.
- Исходная keyset-логика проверена на данных с одинаковыми датами и разными Id через LINQ to Objects. Проверяются pageSize+1, hasNext и курсор последней выданной строки, а не дополнительной. Все четыре исправления интерактива компилируются, имеют проверенные наборы Id и переводятся Npgsql в SQL с ORDER BY/LIMIT.
- Эталон атомарного резервирования компилируется; тестовая модель имеет ключ Inventory.ProductId и уникальный OperationId. Транзакция, affected rows, rollback и гонка двух независимых DbContext на реальной PostgreSQL здесь не выполнялись. Исходный xUnit-фрагмент конкурентного теста сохранён с необходимым контекстом, но не объявляется выполненным тестом БД.
- Реального подключения к PostgreSQL, исполнения SQL, развёртывания RabbitMQ, публикации Outbox или проверки exactly-once эффектов не было. Учебные описания at-least-once, inbox и внешней идемпотентности не заменены более сильными обещаниями.
- На ширине 390 px проверены правильные/неправильные решения пяти заданий, восстановление после перезагрузки и сброс рабочего ответа. Сброс сохраняет ранее полученную отметку успешного выполнения. Консоль без ошибок, горизонтального переполнения нет.
- Повторный импорт и публикация идемпотентны. Основной и резервный каталоги revision 261 совпадают; payload сверены по SHA-256.

Отчёты: `artifacts/aspnet-v2-module14-sdk/results.json`, `artifacts/aspnet-v2-module14-ui-results.json`. APK не пересобирался. Пользовательский код в приложении не выполняется.
