## 1. Rate limiting: пропущен using

Урок `m18-l07`, «Rate Limiting и защита от злоупотребления».

Источник: `server/theory-source/aspnet-core-v2-module18/07_rate_limiting_abuse.md`. В программном примере есть using System.Threading.RateLimiting, но нет пространства имён, содержащего метод расширения AddFixedWindowLimiter.

На .NET 10 исходный блок не собирается:

```text
CS1061: RateLimiterOptions не содержит определения AddFixedWindowLimiter
```

Перед кодом нужно добавить:

```csharp
using Microsoft.AspNetCore.RateLimiting;
```

Копия примера с этим единственным добавлением успешно собрана. Ошибку нужно исправить и в авторском Markdown, и в публикуемом JSON через штатную пересборку контента.

## 2. Метрики: неоднозначный target-typed new

Урок `m20-l07`, «Metrics API: Counter и Histogram».

Источник: `server/theory-source/aspnet-core-v2-module20/07_metrics_counter_histogram.md`, строки 53 и 56.

Исходные вызовы:

```csharp
OrderMetrics.Created.Add(1, new("channel", "web"));
OrderMetrics.Duration.Record(
    Stopwatch.GetElapsedTime(start).TotalSeconds,
    new("channel", "web"));
```

Оба приводят к CS0121: выбор перегрузки между одним KeyValuePair и params-массивом неоднозначен.

Например, использовать явно типизированный тег:

```csharp
var channelTag = new KeyValuePair<string, object?>("channel", "web");
OrderMetrics.Created.Add(1, channelTag);
OrderMetrics.Duration.Record(
    Stopwatch.GetElapsedTime(start).TotalSeconds, channelTag);
```

Эквивалентная замена обоих new на `new KeyValuePair<string, object?>("channel", "web")` проверена компиляцией копии полного примера. Это не ошибка движка метрик, а ошибка исходного C#-примера.

## 3. OutputCache: сделать код самодостаточным

Урок `m21-l08`, «Output Caching: кэширование HTTP-ответов».

Источник: `server/theory-source/aspnet-core-v2-module21/08_outputcache.md`.

Код использует IOutputCacheStore без импорта пространства имён. Копирование только кодового блока приводит к CS0246. **В отличие от пункта 1, необходимый using уже прямо указан в пояснении после блока.** Это замечание к удобству копирования, а не отсутствие инструкции в уроке.

Рекомендуется включить строку непосредственно в блок Program.cs:

```csharp
using Microsoft.AspNetCore.OutputCaching;
```

После добавления копия собирается. В пояснении открытый endpoint инвалидации явно назван учебным; его необходимость защищать правами администратора также указана, поэтому сам по себе этот демонстрационный маршрут не объявляется новой найденной уязвимостью.

## Редакторские наблюдения

- Есть короткие уроки: например, поясняющий текст m16-l04 содержит примерно 213 слов без заголовков и кода. Это само по себе не ошибка: нужны зависимости из предыдущих уроков и полный пример. Для новичков полезно дополнить разбором конфигурации, диагностикой типичных 401 и воспроизводимым локальным сценарием.
- Встречаются два дословно повторённых вопроса: об overposting в m04/m24 и об Outbox в m14/m24. Темы закономерно повторяются в разных контекстах; повтор не является ошибкой ID или ключа. Для проверки переноса знаний лучше сделать поздние вопросы ситуационными.
- Matching составляет 62 из 135 упражнений, то есть около 46%. Все семь механик присутствуют, поэтому это не ситуация «везде один тип». Долю не нужно механически выравнивать; при последующей доработке выбирать механику по учебной задаче.
- Полностью одинаковых объяснений к обычным вопросам автоматическая сверка не обнаружила. Это не доказывает, что все объяснения содержательно достаточны.
