## Модель и проверка

Общие обязательные поля: `id`, `type`, `title`, `description`, `instructions`, `content`, `validation`, `feedback`, `settings`, `version`. Discriminated union разделяет специфические данные семи типов.

- `matching`: `content.left` и `content.right` — по 2–12 элементов `{id,label}`. `validation.pairs` связывает ID левого элемента с ID правого. Поддерживается взаимно однозначное соответствие.
- `sequence`: `content.items` — 2–20 элементов `{id,label}`. `validation.acceptedOrders` — от 1 до 20 допустимых полных перестановок ID. Проверяется совпадение с любой из них.
- `feedback`: непустые строки `success`, `failure`, `explanation`.
- `settings`: `{practice: true, shuffle: true}`; перемешивание можно явно отключить. Оцениваемые упражнения на этом этапе не поддерживаются.
- `version`: положительное целое. ID упражнения уникален в пределах курса; ID элементов уникальны в своей группе. ID содержит латинские строчные буквы, цифры и дефисы, начинается с буквы или цифры.

Валидатор отклоняет неизвестные типы и поля, дубликаты, несуществующие связи, некорректные порядки, неверные размеры и настройки. Проверка сравнивает ID, а не подписи. Никакой код, выражения или HTML из материалов не исполняются. React выводит текст с экранированием, `eval` и новые библиотеки не используются. Ключи проверки находятся в офлайн-контенте; это учебная самопроверка, а не защита экзамена от извлечения ответов.

## Как добавить упражнение

Для текущего Markdown-курса отредактируйте `server/exercise-source/csharp-foundations-v2.json`. Оригинальные Markdown менять не нужно. Каждый объект описывает размещение после стабильного ID блока, например:

```json
{
  "moduleId": "m02",
  "lessonId": "m02-l01",
  "afterBlockId": "theory-2",
  "block": {
    "id": "exercise-example",
    "kind": "exercise",
    "exercise": {
      "id": "example-process-order",
      "type": "sequence",
      "version": 1,
      "title": "Порядок действий",
      "description": "Восстановите порядок работы с результатом вычисления.",
      "instructions": "Переместите элементы кнопками вверх и вниз.",
      "content": {
        "items": [
          {"id": "calculate", "label": "Вычислить результат"},
          {"id": "show", "label": "Показать результат"}
        ]
      },
      "validation": {"acceptedOrders": [["calculate", "show"]]},
      "feedback": {
        "success": "Верно.",
        "failure": "Проверьте порядок.",
        "explanation": "Сначала получают результат вычисления, затем показывают его."
      },
      "settings": {"practice": true, "shuffle": true}
    }
  }
}
```

Добавьте объект в массив, сохранив существующие упражнения. Затем выполните:

```powershell
npm.cmd run content:import:csharp
npm.cmd test
npm.cmd run build
npm.cmd run content:publish
```

Импорт автоматически повышает версию курса при изменении; повторный импорт без правок её сохраняет. Исходный JSON курса генерируется заново, поэтому упражнения для C# редактируют именно в exercise-source. В других JSON-курсах блок `exercise` можно вставить непосредственно в `modules[].lessons[].blocks[]`, повысив версию курса. Публикация валидирует упражнения общим валидатором. Несколько размещений после одного якоря сохраняют порядок в массиве.

При разработке Vite игнорирует каталог server, чтобы публикация не перезагружала открытые тесты. После импорта новых материалов перезапустите dev-сервер. Для телефона потребуется новая APK со встроенной поддержкой упражнений. Старый клиент не сможет отобразить новый тип блока; его ранее загруженные материалы сохраняются при ошибке обновления.

## Сохранения и совместимость

Состояния хранятся в `LearningAttempt.exercises` в существующем ключе курса через localStorage / Capacitor Preferences. Сохраняются выбранные пары, текущий порядок, порядок вариантов, число проверок, последняя проверенная попытка и успешное решение. «Начать заново» очищает текущее решение и обратную связь, но сохраняет число попыток и факт прежнего успеха. Повторное нажатие проверки без изменения ответа не добавляет попытку. Повторное прохождение тестов курса сохраняет упражнения.

При восстановлении проверяется форма ответа и результат успешной попытки. Изменение содержимого или версии упражнения сбрасывает только его состояние; остальные упражнения и тестовые ответы сохраняются. Старые сохранения без `exercises` поддерживаются. Добавление только тренировочных блоков сохраняет завершённость ранее сданного курса и неизменный результат экзамена.

## Этап 2: сборка кода из фрагментов

Новый тип `code-order` проверяется по ID фрагментов, а не по тексту или фактическому выполнению программы. Идентичный текст у двух фрагментов разрешён: их ID должны различаться. Для взаимозаменяемых фрагментов автор перечисляет все допустимые порядки.

`content` содержит:

- `language`: короткое обозначение языка (`csharp`, `python`, `javascript`, `c++` и др.). Оно используется для подписи, а не для выбора исполняющей среды.
- `fragments`: от 2 до 20 объектов `{id, code}`, до 8000 символов в каждом непустом фрагменте. Сохраняются все пробелы, табуляция, специальные символы и переносы строк.
- необязательный `context`: исходный контекст задачи, показываемый отдельно;
- необязательные `prefix` и `suffix`: фиксированные части собираемой программы до и после фрагментов.

`validation.acceptedOrders` содержит от 1 до 20 полных перестановок ID. Каждый ID должен присутствовать ровно один раз. Проверка неполного ответа возвращает неуспех, а редактирование, предпросмотр и восстановление текущего состояния не допускают потерянных или повторных фрагментов. При новой версии или изменённом наборе фрагментов старый ответ сбрасывается только для этого упражнения.

Предпросмотр собирается как `[prefix, ...фрагменты_в_текущем_порядке, suffix].join("\n")`, пропущенные фиксированные части не добавляются. Контекст в результат не включается. Отступы не вычисляются автоматически: их заранее задаёт автор. В проекте нет подсветки синтаксиса, поэтому используется моноширинное отображение с горизонтальной прокруткой внутри фрагмента. HTML выводится как текст. Тяжёлый редактор и библиотеки не добавлены.

При `shuffle: true` стартовый порядок перемешивается. Если случайно получен допустимый вариант, выбирается неправильная перестановка, когда она существует. Если автор разрешил все возможные перестановки, неправильного порядка не существует. При `shuffle: false` порядок фрагментов определяется массивом автора.

После проверки пользователь может исправить порядок напрямую, нажать «Повторить попытку» (сохраняет порядок и убирает обратную связь) либо «Начать заново» (заново перемешивает фрагменты). Проверки, успешное решение и последняя проверенная попытка сохраняются по правилам этапа 1; сброс не стирает число проверок и прошлый успех. Кнопки вверх/вниз доступны с клавиатуры и на сенсорном экране.

```json

  "afterBlockId": "theory-2",

    "kind": "exercise",

      "instructions": "Переставьте фрагменты и проверьте сборку.",
      "content": {
        "language": "csharp",
        "context": "Консольное приложение C#.",
```

## Этап 3: поиск и исправление ошибки

`code-debug` содержит исходный код с нумерацией строк. Сначала пользователь выбирает строку нажатием или клавиатурой (Tab, Enter/Пробел), затем — вариант исправления. Можно изменить оба выбора без сброса всего задания. Предпросмотр подставляет выбранное исправление в выбранную физическую строку; он не является подтверждением правильности и ничего не исполняет.

Проверка различает `incomplete`, `wrong-line`, `wrong-fix`, `correct`. Для незавершённого ответа кнопка проверки отключена, попытка не засчитывается. До отправки нет подсветки правильной строки, объяснений и ключей. После проверки явно сообщается, неверно ли найдено место или неверно выбрано исправление. Разбор раскрывает причину и все разрешённые исправления.

### Модель

Общие поля упражнения остаются прежними. Специфические данные:

- `content.language`: обозначение языка;
- `content.code`: исходный код до 20 000 символов / 300 строк, LF или CRLF;
- `content.errors`: массив известных ошибок. В этой версии строго одна ошибка `{id, location: {kind: "line", line: N}, explanation}`;
- `content.fixOptions`: от 2 до 12 вариантов `{id, code}`. Код замены непустой, до 8000 символов; это целая строка или многострочный фрагмент с отступами, заранее подготовленными автором;
- `validation.acceptedFixes`: объект, сопоставляющий ID ошибки одному или нескольким ID допустимых исправлений.

Номера строк начинаются с 1 и включают пустые строки. Ошибка не может ссылаться на пустую или отсутствующую строку. Проверка использует позицию и ID исправления: одинаковый текст в разных строках не смешивается. Поле location имеет собственный discriminant `kind`, чтобы позже добавить диапазоны без изменения общего формата; сейчас диапазоны отклоняются валидатором. Массив errors сохраняет возможность будущего расширения на несколько мест, но несколько ошибок пока не поддерживаются и явно отклоняются.

Ответ: `{type: "code-debug", selection?: {kind: "line", line: N}, fixId?: "option-id"}`. Пустой ответ и выбор только строки — допустимые незавершённые состояния; неизвестные строки, поля, ID или исправление без строки отклоняются. При восстановлении проверяются ответ, порядок вариантов, последняя проверка и успешное решение.

Состояние сохраняется через существующий LearningAttempt.exercises: строка, исправление, число попыток, факт успеха и последняя проверенная попытка восстанавливаются после перезагрузки. «Повторить попытку» сохраняет выбор и снимает обратную связь. «Начать заново» очищает строку и исправление, но сохраняет число проверок и прежний успех — как в этапах 1–2. Изменение версии, исходного кода, вариантов или описания ошибки сбрасывает только изменённое упражнение. Тестовые ответы и состояния других типов не затрагиваются.

## Этап 4: преобразование данных

Тип `data-transform` работает через общую модель Exercise, существующие уроки, импортёр и LearningAttempt.exercises. Отдельного сервиса вычислений, интерпретатора, редактора кода или зависимостей нет. Операции — ограниченные JSON-декларации; функции и исполняемые выражения не принимаются.

### Прохождение

Пользователь видит условие, исходную коллекцию, целевой результат и требования к операциям. Выбирает операцию в списке, задаёт разрешённые параметры и нажимает «Добавить операцию». Цепочку можно редактировать, удалять шаги и перемещать их кнопками ↑/↓ (доступны клавиатура и сенсорный экран). Редактирование требует кнопки «Сохранить операцию»; введённый, но не сохранённый черновик формы не является частью цепочки.

Под каждым шагом доступны промежуточные данные и число элементов; если автор задал explanation операции, оно показывается с результатом шага. Исходные объекты и результаты отображаются таблицами с прокруткой внутри таблицы, простые массивы — компактным JSON, группы — отдельными раскрываемыми блоками. Внизу всегда есть текущее состояние.

«Отменить последний шаг» удаляет последний элемент цепочки; это не история отмен всех действий редактора. «Начать заново» очищает цепочку и черновик формы, сохраняет число проверок и факт прежнего успеха. «Повторить попытку» оставляет цепочку, но снимает обратную связь. До проверки готовая цепочка и объяснение решения не показаны. После проверки выводится результат каждого условия.

### Операции и точная семантика

- `filter` / Where: ==, !=, >, >=, <, <= для чисел. Для строк и boolean — только == и !=. Значения не приводятся между типами: строка «25» не сравнивается с числом 25. Значение фильтра выбирается из авторского списка.
- `select` / Select: выбирает одно или несколько полей объекта в объект (`mode: object`) либо одно поле в массив скаляров (`mode: scalar`). Отсутствующие или уже удалённые поля — ошибка. Проекция скалярного списка не поддерживается.
- `order-by` / OrderBy: числовая либо строковая сортировка asc/desc. Строки сравниваются лексикографически по кодовым единицам UTF-16, с учётом регистра, без локали и нормализации Unicode. Сортировка стабильна: при равных ключах сохраняется прежний порядок.
- `then-by` / ThenBy: добавляет ключ к основной сортировке. Допустим непосредственно после OrderBy или ThenBy. Filter/Select/GroupBy/Count прекращают такой контекст.
- `group-by` / GroupBy: группирует по одному полю либо по самому скалярному значению. Группы идут в порядке первого появления ключа, элементы внутри — в исходном порядке.
- `count` / Count: mode all возвращает число элементов списка; после GroupBy — число групп. Mode groups требует GroupBy и возвращает список объектов `{key, count}` с числом элементов каждой группы.

Поле `$value` обозначает сам элемент скалярной коллекции. После группировки в этой версии можно применить Count, но не фильтровать или сортировать непосредственно коллекцию групп. После Count(groups) снова получается обычный список объектов с полями key/count, к которому можно применять разрешённые автором операции.

При некорректном контексте появляется понятное сообщение, вычисление останавливается на проблемном шаге. Последующие шаги отмечаются как невыполненные. Показано последнее корректное состояние, его нельзя выдать за правильный итог: условие выполнения всей цепочки не проходит. Удаление, перестановка или редактирование ошибочной операции восстанавливает вычисление без перезагрузки.

### Формат данных

Общие id/type/title/description/instructions/version/feedback/settings не изменены. В content:

- `source`: однородный массив до 100 элементов. Значения — конечные числа, boolean или строки до 500 символов; объекты — плоские, с одинаковым набором полей и типами по схеме. Null, вложенные объекты и массивы в полях пока не поддерживаются.
- `schema`: `{kind: "scalar", valueType: "number"}` (также string/boolean) или `{kind: "object", fields: {name: "string", age: "number"}}`. Схема сохраняет смысл полей даже для пустой коллекции.
- `operations`: 1–20 определений с уникальными id, type, title и необязательным explanation. Для каждого типа валидируются свои параметры: fields/operators/values, fields/modes, fields/directions, fields либо modes.
- `target`: `{kind: "list", items: [...]}`, `{kind: "groups", groups: [{key, items}]}` или `{kind: "count", value: N}`.
- `presentation`: generic/linq/sql/python. Меняет подписи операций, а не их семантику; это не выполнение SQL или Python.

Названия полей — латинские буквы, цифры и подчёркивания, начиная с буквы, до 60 символов; до 12 полей. Специальный селектор $value разрешён для скаляров. Имена __proto__, constructor и prototype запрещены. Обращение к полям требует Object.hasOwn. Для групп используется Map с типизированным JSON-ключом, поэтому строковое значение «__proto__» остаётся безопасными данными.

Объявления операций:

- filter: fields (допустимые селекторы), operators (допустимые сравнения), values (1–30 разрешённых скалярных значений);
- select: fields и modes (object/scalar);
- order-by / then-by: fields и directions (asc/desc);
- group-by: fields;
- count: modes (all/groups).

Шаг хранит operationId, type и конкретные параметры из разрешённого набора. Число шагов жёстко ограничено 12. Ограничения размеров предотвращают неограниченный рост вычислений: нет объединений или операций, размножающих строки. Движок не мутирует source, сохраняет промежуточные состояния и сортирует копии данных.

### Проверка

Validation содержит:

- `order`: ordered/unordered для строк списка и элементов внутри групп;
- `groupOrder`: ordered/unordered для порядка групп;
- `requiredOperations`: виды операций, которые обязательно использовать;
- `forbiddenOperations`: виды операций, которые нельзя использовать;
- `maxSteps`: 1–12, авторское ограничение, проверяемое отдельно от жёсткого лимита;
- `solution`: непустая эталонная цепочка для разбора и проверки корректности самого задания при импорте.

Оценка НЕ сравнивает пользовательскую цепочку с solution. Сравнивается итог и каждое ограничение. Пустая цепочка не считается выполненным упражнением. Объекты канонизируются по именам полей, поэтому порядок свойств JSON не влияет. Значения и типы сравниваются точно; для unordered сравниваются мультимножества с сохранением повторов. Для групп проверяются ключи, содержимое и заданные правила порядка. Разные цепочки принимаются, если совпал результат и выполнены все требования.

Эталон при импорте должен реально выполняться и удовлетворять цели и ограничениям. Неизвестные поля/операции, недопустимые параметры, несоответствие схеме, ошибочные ссылки и противоречивые требования отклоняются. Неудачный промежуточный контекст пользователя — учебная ошибка, а не повреждённое сохранение.

## Этап 5. Пошаговая трассировка (`code-trace`)

Текущий курс: версия **24**, 19 модулей, 177 уроков, **14 интерактивов**. Оцениваемые вопросы не изменены. Этап 6 не реализован.

### Движок и интерфейс

`src/lib/codeTraces.ts` содержит типы, строгую валидацию, чистые переходы, предсказания и оценку. `src/exercises/CodeTraceInput.tsx` отображает сценарий через общие Select, стили кода и ответов; ExercisePlayer и exercises.ts обеспечивают общие завершение, сброс и сохранение. Отдельного хранилища или интерпретатора нет.

`content.initial` — обязательный самостоятельный снимок до выполнения, phase=initial и lines=[]. `content.steps` — полные снимки после обозначенной операции, phase=after и lines с номерами подсвеченных строк, начиная с 1. Одна строка может повторяться, например условие и увеличение счётчика for. Номер шага и номер строки независимы. Для многострочной операции задаются несколько lines. В async-примере шаги обозначают причинные события; снимок не фиксирует поток и момент возврата SetResult относительно продолжения.

Снимок содержит id, title, explanation, variables, objects и необязательный output. Назад выполняется выбором готового снимка, без попыток отменить операции. Изменения переменных и объектов сравниваются с предыдущим снимком сценария, независимо от направления просмотра. Новые переменные/объекты отмечены текстом; объявленный тип и область видимости видны в таблице. Код отображается как текст с номерами строк, без HTML-вставок. На широком экране две колонки, на телефоне одна; длинный код прокручивается внутри панели.

Значения — discriminated union:

- `{kind:"scalar",value: 5}`: конечное число, строка, boolean или null. Строка `"null"` отображается с кавычками и отличается от null.
- `{kind:"reference",objectId:"person-1"}` либо objectId=null. Ссылка отделена от объекта.
- `{kind:"record",fields:{Name:{kind:"scalar",value:"Alex"}}}` — структурированное значение.
- `{kind:"array",items:[...]}` — ограниченный массив значений.

Объект `{id,type,fields}` существует отдельно от переменных. ID стабилен и условный, без адресов памяти; текст «→ Person #person-1» служит альтернативой графу. Две одинаковые ссылки указывают на один объект; равные поля сами по себе не означают идентичности. Поддерживаются ссылки между объектами и null-ссылки.

output отсутствует — панели нет; output=[] — «Вывода пока нет»; output=[""] — одна явно обозначенная пустая строка. Каждый снимок задаёт весь накопленный вывод, поэтому переход назад восстанавливает его точно.

### Практика и предсказания

Демонстрация разрешает свободно выбирать любой шаг. Практика разрешает переходы лишь до первого ещё не проверенного предсказания включительно. Список шагов содержит только номера доступных состояний, без будущих заголовков, значений или объяснений. Вопрос относится к **следующему** снимку после atStepId.

Поддерживаются kind=variable (variableId и типизированные варианты value), output (варианты output), reference (variableId и варианты objectId), state (варианты description). У каждого вопроса id, atStepId, prompt, options, correctOptionId, explanation. Варианты 2–6; ID стабильны. Правильные variable/output/reference проверяются валидатором на соответствие следующему снимку. Правильность текстового state задаётся автором, C# автоматически не анализируется.

«Проверить предсказание» фиксирует выбор и увеличивает счётчик ровно один раз. До проверки кнопка вперёд заблокирована; после проверки, в том числе неверного ответа, открываются следующий шаг, правильный ответ и объяснение. Для исправления есть «Повторить предсказание». Повторное посещение проверенного шага или повторное завершение не добавляет попыток. Переключение режима возвращает к начальному состоянию, сохраняя ответы; просмотр демонстрации сам по себе не открывает вопросы практики.

validation.completion=practice требует дойти до конца в практике и проверить все предсказания; завершение с неверными ответами фиксируется как неуспешная попытка, после исправлений можно завершить снова. completion=either также допускает просмотр до конца в демонстрации. Для успешной практики все текущие проверенные ответы должны быть верны. Упражнение необязательное, не влияет на точность, награды или итоговые оценки курса.

### Сохранения, сброс и совместимость

В LearningAttempt.exercises хранятся mode, stepId, furthestStepId, responses (choiceId, checkedChoiceId, firstChoiceId, attempts), общий счётчик и checkedAnswer/solvedAnswer. Снимки программы не копируются в прогресс; для code-trace fingerprint — компактный детерминированный отпечаток версии и содержимого. Смена содержимого сбрасывает только это упражнение. Удалённые упражнения отбрасываются. Остальные типы и прежние результаты курса сохраняются.

«К началу трассировки» возвращает к initial с сохранением ответов и открытых шагов. Общая кнопка «Начать заново» очищает текущий проход и ответы, сохраняя накопленные проверки и факт прежнего успеха, как у других упражнений. При обновлениях курса архивируется одна предыдущая версия сохранения без рекурсивно вложенных архивов: это устраняет рост localStorage после последовательных обновлений.

### Модель компонентов, узлов и отношений

`ArchitectureExercise` расширяет общий Exercise полями type=architecture-builder, content и validation. Общие id/version/title/description/instructions/feedback/settings не меняются.

content содержит:

- components: описания доступных компонентов `{id,label,category,maxInstances,allowedRelations,description?,icon?,roles?}`. Описание компонента существует независимо от размещённых экземпляров. Названия, категория, описания и иконки отображаются обычным текстом.
- roles: необязательный список `{id,label}` внутри компонента. Если он задан, экземпляр обязан выбрать роль, а одна роль не может встречаться дважды. Палитра предоставляет отдельную кнопку добавления каждой роли. Без roles экземпляры одного componentId взаимозаменяемы.
- relations: произвольные авторские `{id,label,directed}`. Имена не зашиты в C#-движок. allowedRelations компонента перечисляет допустимые ID отношений для обоих концов связи.
- untyped: необязательное `{label,directed}` для связи без семантического типа. В allowedRelations такая связь обозначается служебной строкой `untyped`; явный relation с таким ID запрещён.
- allowSelfEdges: разрешает или запрещает петли на одном узле.

Размещённый узел `{id,componentId,role?,x,y}` хранит уникальный ID экземпляра и нормализованные координаты 0..1. Название и категория берутся из определения компонента, без дублирования в сохранении. Связь `{id,source,target,relationId?,directed}` соединяет ID **экземпляров**, а не типы. При отсутствии relationId используется untyped. Направленность обязана совпадать с определением отношения. Разные типы связи между одинаковыми концами различаются; точный дубликат запрещён. У ненаправленных связей перестановка концов не создаёт новую связь.

### Эталоны, разрешённые дополнения и запреты

validation содержит:

- feedbackMode: learning или assessment.
- variants: 1–10 альтернативных вариантов графа. Каждый `{id,nodes,edges,extraComponents,extraEdges}` содержит обязательные узлы `{id,componentId,role?}` без координат и обязательные связи между эталонными ID. Шаблонные ID не обязаны совпадать с пользовательскими.
- extraComponents: ID типов, дополнительные экземпляры которых разрешены конкретным вариантом, в пределах maxInstances и свободных ролей. Пустой список означает запрет лишних узлов.
- extraEdges: разрешённые дополнительные связи по семантическим шаблонам.
- forbiddenComponents: запрещённые типы среди доступных компонентов. Это позволяет добавить отвлекающие элементы в палитру.
- forbiddenEdges: глобальные запрещённые семантические связи.

Шаблон связи `{sourceComponentId,targetComponentId,sourceRole?,targetRole?,relationId?,directed}` описывает типы и необязательные роли концов. Отсутствующая роль означает любую роль этого типа. Для ненаправленных шаблонов концы взаимозаменяемы. Предусмотренные в варианте обязательные или дополнительные связи не могут одновременно запрещаться; обязательный/допустимый дополнительный компонент не может быть forbidden. Дополнительные связи с запрещёнными компонентами также отклоняются. Неизвестные, повторные и перекрывающиеся правила запрещены.

### Как проверяется граф

Проверяются экземпляры, их типы/роли и отношения, **не координаты**. Для каждого варианта движок подбирает взаимно однозначное соответствие обязательных шаблонных узлов пользовательским экземплярам того же componentId и роли. Если роли отсутствуют, перебираются ограниченные перестановки. Поэтому два одинаковых Subscriber можно добавлять и располагать в любом порядке.

Для каждого соответствия проверяются обязательные узлы и связи, лишние компоненты и связи, разрешённые дополнения и глобальные запреты. Ребро сравнивается по концам, relationId и направленности. Для правильного результата достаточно целиком удовлетворить одному варианту; правила разных вариантов не объединяются. В случае ошибки возвращается ближайший вариант по числу нарушенных условий: список отсутствующих компонентов/связей и ID неправильных узлов/связей. Неправильный тип или направление даёт отсутствующую обязательную связь и явно указанную неправильную фактическую связь.

Алгоритм не выполняет пользовательский код и не реализует изоморфизм больших графов. До импорта оценивается верхняя граница подстановок: произведение P(maxInstances, число обязательных экземпляров) для типов без ролей, суммарно по вариантам. **Не более 20000 полных соответствий**. Роли сокращают перебор до однозначных кандидатов. Если лимит превышен, автор должен добавить роли или уменьшить максимумы/число вариантов; валидный опубликованный сценарий не прерывается посреди проверки с неопределённым результатом.

### Управление и мобильный экран

На широком экране слева палитра, справа схема. На телефоне: компоненты, схема, инструменты связей, текстовый список и проверка. Горизонтальная прокрутка ограничена схемой минимальной ширины 640px; вся страница не должна расширяться.

Узлы добавляются кнопками. Нажатие выбирает узел, показывает перемещение кнопками и удаление, а также устанавливает его исходным компонентом новой связи. Можно перетащить узел мышью/касанием или сдвинуть стрелками клавиатуры: 0.05, с Shift 0.01. Кнопки инструментов перемещают на 0.1. Координаты ограничиваются диапазоном 0..1. Во время перетаскивания локально рисуется предпросмотр; в сохранение и историю попадает одно итоговое действие.

Форма «Откуда → Куда → Отношение → Создать связь» полностью работает через общие Select и клавиатуру. Рисовать линию мышью не требуется. Тип связи можно изменить после её выбора; есть удаление отдельной связи. При удалении узла автоматически удаляются все инцидентные связи. Линии доступны по SVG и текстовому списку; ошибки и выбранные элементы выделены. Подписи полного текста и типов доступны в списке, даже если короткая подпись узла не помещается.

У SVG фиксированная система координат 1000×600, синхронизированная с процентными позициями HTML-кнопок. При перемещении и изменении ширины линии пересчитываются/масштабируются вместе с узлами. Для параллельных связей используются простые кривые и номера, соответствующие нумерованному списку; автоматической маршрутизации и предотвращения пересечений нет.

«Отменить действие» отменяет добавление, удаление, изменение типа, перемещение и очистку; хранится 10 предыдущих графов. «Очистить схему» — отменяемое действие. Общая «Начать заново» создаёт пустой граф без истории, сохраняя общий счётчик проверок и факт прежнего успеха, как в остальных интерактивах.

### Обратная связь и сохранения

Learning после проверки показывает все условия, ошибки, объяснение и пример допустимой схемы. Assessment показывает только вердикт. Подробности, подсветка ошибок и пример скрыты до явной кнопки «Завершить попытку и открыть разбор». Действие закрытия не добавляет проверку. Повторная попытка открывает редактирование без разбора; изменение структуры также скрывает прежние подсказки. Это учебный интерфейс, не защита от чтения локального JSON пользователем.

Общие ExerciseState и LearningAttempt.exercises сохраняют GraphAnswer `{type,graph,undo,closed}`, количество attempts, checkedAnswer и solvedAnswer. Координаты в том же диапазоне корректны на экране другого размера. После перезагрузки восстанавливаются узлы, связи, позиции, история отмены и результат. Выбор узла и незавершённая форма связи являются временным интерфейсным состоянием.

Перемещение и перестановка списков не меняют семантический ключ ответа, поэтому не сбрасывают последнюю проверку и не увеличивают attempts. Добавление/удаление узлов, изменение типа/концов или удаление связи снимают текущую проверку. Повторный клик проверки без изменений идемпотентен; отдельная «Повторить попытку» позволяет проверить ещё раз осознанно. Сохранённый прежний успех остаётся виден после повторения.

У architecture-builder компактный fingerprint версии и содержимого, как у code-trace. При изменении версии/описания/правил сбрасывается только изменённое упражнение. Удалённые типы/отношения не восстанавливаются в новую версию. Остальные типы упражнений и оценки курса сохраняются.

### Лимиты

До 20 определений компонентов и 20 размещённых узлов, до 40 связей, до 20 типов отношений, до 10 вариантов, до 40 дополнительных/запрещённых шаблонов в каждом списке. maxInstances 1–20; до 20 ролей на компонент. Название/категория/роль до 80 символов, подпись отношения до 120, описание компонента до 1000, иконка до 20. JSON content+validation до 250000 символов. До 10 графов в undo. Верхняя граница проверки 20000 соответствий; петли только при allowSelfEdges=true. Неизвестные поля, ID, отношения, несогласованная направленность, превышения, отсутствующие концы, дубликаты и противоречивые эталоны отклоняются до отображения.

### Где попробовать три задания

Стабильные mXX не совпадают с экранным номером из-за переноса вводного модуля в конец. Все интерактивы вставлены **после theory-2**:

1. m08 / m08-l07 «ООП» → «Интерфейсы и реализация контрактов»: **csharp-graph-oop**. IAnimal, Animal, Dog, Cat. Animal→IAnimal implements, Dog/Cat→Animal inherits. Реализация интерфейса наследуется производными классами через базовый. Learning.
2. m12 / m12-l06 «Делегаты, лямбда-выражения и события» → «События: издатель, подписчик и event»: **csharp-graph-events**. Publisher, условное обозначение Event, два взаимозаменяемых Subscriber, отвлекающий Timer. Publisher предоставляет и вызывает событие; подписчики регистрируют обработчики и получают вызовы. Event — учебное обозначение, не обещание отдельного runtime-объекта. Assessment.
3. m17 / m17-l10 «Многопоточность и синхронизация» → «Channel<T>: producer–consumer и backpressure»: **csharp-graph-channel**. Producer→Channel<T> writes-to, Channel<T>→Consumer reads-from. Здесь стрелки обозначают поток данных; reads-from не изображает направление вызова метода чтения. Database и Logger запрещены в базовом ответе. Learning.
