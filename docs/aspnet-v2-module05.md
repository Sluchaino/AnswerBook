# ASP.NET Core — Middleware и HTTP-конвейер

Пятый модуль добавлен по десяти исходным файлам уроков, контрольному тесту и ключу. Оригиналы сохранены в `server/theory-source/aspnet-core-v2-module05/`. Курс `aspnet-core-foundations-v2` v32, каталог revision 212.

Модуль содержит десять уроков, 20 мини-проверок, 50 итоговых вопросов уроков и 20 контрольных — всего 90 вопросов с пояснениями. Пять интерактивов размещены по одному в уроках 3, 4, 5, 6 и 8: порядок делегатов, short-circuit, ветвление, сборка класса и исправление положения limiter. При сборке класса принимаются оба допустимых порядка поля и конструктора. Дополнительные уроки не создавались.

Теперь доступны пять модулей из 27: 43 урока, 25 интерактивов, 86 мини-проверок и 315 вопросов на оценку. Модули 6–27 показывают «Скоро появится». Первые четыре модуля и их размещения упражнений сохранены; C# и его sidecar сверены по SHA-256.

## Адаптация материалов

Служебный ключ использует заголовки вида «Урок 01 — М1» и «Контрольный тест — К1»; адаптер читает их без изменения ID вопросов. Авторские рекомендации, ответы и источники не включаются в ученическую теорию.

Реальная компиляция выявила вызов `TypedResults.Accepted()` без обязательного URI. В публикуемом примере урока 2 он заменён на `TypedResults.Accepted((string?)null)`, сохраняя ожидаемый статус 202 без Location. В примере rate limiter урока 8 добавлен `using Microsoft.AspNetCore.RateLimiting;` для расширения AddFixedWindowLimiter. Оригинальные Markdown не изменены; тест проверяет обе точечные адаптации.

В упражнении limiter принимаются явный порядок UseRouting → UseRateLimiter и вариант без явного UseRouting: WebApplication сам добавляет маршрутизацию. Неверный порядок с явным UseRouting после limiter и удаление limiter не обеспечивают ограничение. Проверка HTTP различает первые пять успешных запросов и отклонение шестого в том же окне.
