# Уведомления о материалах

Реализованы история изменений внутри сайта/приложения и периодическая фоновая проверка Android. Отдельный push-сервер не используется. Рабочее хранилище не изменялось; подготовлен локальный каталог revision 270.

## Для пользователя

- Колокольчик в верхней панели открывает последние 100 уведомлений, показывает число непрочитанных, позволяет отметить одно или все сообщения прочитанными и открыть карточку курса.
- Уведомления о новых курсах и об изменениях существующих объединены по выпуску курса: одно сообщение на courseId/version, внутри — список новых модулей, новых/обновлённых уроков или обновлённых модулей. Новый модуль не создаёт отдельное сообщение на каждый вложенный урок.
- На первом запуске существующие материалы принимаются за начальную точку: сотни исторических уведомлений не создаются.
- Первое появление отпечатков в старом каталоге само по себе не создаёт сообщение. Пока подробных отпечатков нет с обеих сторон, используется общее сообщение об обновлении курса.
- На Android системные уведомления включаются отдельной кнопкой внутри окна уведомлений. На Android 13+ запрашивается системное разрешение. Отказ не мешает пользоваться приложением и внутренней историей.
- Системные уведомления можно выключить в этом же окне; Android-настройки позволяют отдельно управлять каналом «Обновления материалов».
- Нажатие системного сообщения открывает окно уведомлений приложения. Переход к курсу не скачивает материалы автоматически.
- Если фоновой проверке уже известен новый курс, а текущий каталог приложения ещё не обновлён, нужно подключиться к сети и обновить каталог прежде, чем открывать карточку.

## Когда проверяются изменения

- В открытом приложении: при запуске, возвращении, восстановлении соединения, вручную кнопкой «Обновить каталог», а также примерно раз в 15 минут, пока страница видима.
- На Android после включения системных сообщений: уникальная периодическая задача WorkManager, интервал один час, доступная сеть и не низкий заряд.
- Android может задерживать работу при Doze, ограничениях батареи или производителя. Принудительная остановка приложения системной кнопкой может остановить работу до следующего ручного запуска. Интервал не является гарантией доставки в точный момент.
- В обычном закрытом браузере фоновой проверки нет: service worker и Web Push не добавлялись.

Системный worker получает только HTTPS catalog.json с ограничением 1 МБ и тайм-аутами. Пакеты курсов не скачиваются. Ответы и учебный прогресс в запрос не входят. Фоновая проверка не требует Google/Firebase-токенов и не использует точные будильники.

## Обработка изменений

`scripts/publish-learning.mjs` добавляет в лёгкие описания модулей и уроков необязательное поле contentHash (SHA-256). В него входят соответствующие данные источника, включая теорию и проверки. Это метаданные обнаружения изменений; проверка целостности полного файла курса продолжает использовать SHA-256 файла.

Версию курса нужно повышать при изменениях содержания, сохраняя ID существующих модулей и уроков. Повторный запрос того же выпуска, простое повышение revision каталога, скачивание курса и удаление материалов не создают повторных сообщений. Старый revision игнорируется; откат версии курса отклоняется.

На Android snapshot сравнения, история и прочтение находятся в собственных SharedPreferences. Один синхронизированный механизм обслуживает и worker, и foreground bridge, чтобы их одновременная работа не затирала историю. Состояние сохраняется до показа системного уведомления. Доставка системного сообщения не гарантируется при аварийном завершении между сохранением и вызовом NotificationManager; история при этом остаётся.

Для сайта тот же алгоритм реализован на TypeScript с последовательными записями в локальное хранилище. В интерфейсе отображается только текст, без выполнения содержимого уведомлений. При повреждённом журнале он не перезаписывается молча.

## Проверка

- 475 тестов JavaScript/TypeScript прошли.
- Нативные исходники Android компилируются; два JVM-теста прошли, включая 13 общих сценариев сравнения с браузером.
- Проверены добавление курса/модуля/урока, изменение урока/модуля, отсутствие повторов, сохранение отметки прочтения, ограничение истории, совместимость со старыми метаданными, игнорирование старого revision и отказ от понижения версии.
- В браузере на изолированном тестовом каталоге проверены пустое состояние, появление уведомления с двумя изменениями, прочтение, отсутствие повторного сообщения после синхронизации и мобильная ширина 390 px. Снимок `artifacts/course-notifications-mobile.png` содержит тестовое изменение версии 119 и не является опубликованным выпуском курса.
- Нативные permission dialog, доставка при закрытом приложении, тап системного сообщения и Doze не проверены на устройстве: подключённого Android-устройства/эмулятора нет. JVM-проверки не подменяют такой тест.

Журналы: `artifacts/course-notifications-tests.log`, `artifacts/course-notifications-build.log`, `artifacts/course-notifications-android.log`.

## Выпуск

Для телефона нужна новая сборка APK с bridge и worker. В этой задаче APK для установки не выпускался.

Для будущих точных уведомлений об уроках следует загрузить подготовленный `artifacts/s3-upload/revision-270/catalog.json`. Если соответствующего пакета курса ещё нет в хранилище, сначала загрузить пакеты из courses/, затем catalog.json. Эта операция пока не выполнялась. Пакеты C# v114 и ASP.NET Core v118 не изменились относительно revision 269: в revision 270 изменены метаданные каталога.

При добавлении следующих материалов использовать обычный порядок: изменить источник и повысить версию → content:publish → content:prepare:s3 → загрузить пакеты → заменить catalog.json. Изменение только contentHash без повышения версии курса не используется как новый выпуск.

Основа Android-реализации: [WorkManager](https://developer.android.com/jetpack/androidx/releases/work), [периодическая работа и ограничения времени](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work).
