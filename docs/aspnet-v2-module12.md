# ASP.NET Core — EF Core: запросы и изменения

Двенадцатый модуль добавлен по одиннадцати файлам уроков, контрольному тесту и ключу. Оригиналы без изменений находятся в `server/theory-source/aspnet-core-v2-module12/`. Курс `aspnet-core-foundations-v2` v78, каталог revision 250.

Одиннадцать уроков содержат 22 мини-проверки, 55 итоговых вопросов уроков и 20 контрольных — всего 97 с пояснениями. Пять интерактивов размещены по одному в уроках 2, 5, 6, 8 и 10: границы SQL-трансляции, tracking, сборка добавления товара, bulk-эффекты и классификация конфликта конкретного SKU-ограничения. Дополнительные уроки не создавались.

Доступны двенадцать модулей из 27: 111 уроков, 60 интерактивов, 222 мини-проверки и 795 вопросов на оценку. Модули 13–27 показывают «Скоро появится». Первые одиннадцать модулей и их размещения упражнений сохранены; курс C# и его sidecar сверены по SHA-256. Источники и ключи не отображаются в ученической теории. Code fences сохранены без исправлений.

## Проверки

- 422 автоматических теста и семь API-проверок проходят. Веб-сборка успешна. Lint содержит восемь прежних предупреждений; сборщик предупреждает о размере основного JS-файла.
- `scripts/check-aspnet-v2-module12.mjs`: девять успешных сценариев на .NET 10 и Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3. Проверены перевод фильтров, ILIKE, ANY, named query filters, offset/keyset, DTO-проекции и агрегат Count, состояния ChangeTracker, изменение preview при добавлении Take и отказ трансляции пользовательской функции в Where.
- Для проверки SQL исходные терминальные ToListAsync заменены в проверочном проекте на ToQueryString; запросы к PostgreSQL не отправлялись. Необходимые свойства IsDeleted/TenantId и CurrentTenantId добавлены в тестовую модель, как требует контекст материала. Проверка трансляции не подтверждает планы, индексы и производительность реальной БД.
- Скомпилированы исходные фрагменты Add/AddRange/нормализации DTO, обновления/удаления, ExecuteUpdate/ExecuteDelete, общей транзакции, linked cancellation, endpoint и регистрации диагностики. Они помещаются в соответствующие методы с заданными аргументами; выполнение CRUD/bulk на настоящей БД не заявляется.
- Эталон сборки вставки выполнен с SaveChangesInterceptor, который проверяет Added до сохранения, задаёт тестовый Id=77 и подавляет запись. Проверяются вызов сохранения до ответа 201 и Location /api/products/77. Это проверка последовательности, а не серверной генерации ключа PostgreSQL или обработки настоящего сбоя сохранения.
- Все четыре исправления классификатора скомпилированы и проверены на синтетических DbUpdateException/PostgresException: нужная уникальность, другое уникальное ограничение, FK и технический сбой. Только эталон принимает исключительно SQLSTATE 23505 + UX_products_sku.
- На ширине 390 px проверены правильные/неправильные решения пяти заданий, восстановление после перезагрузки и сброс рабочего ответа. Сброс сохраняет ранее полученную отметку успешного выполнения. Консоль без ошибок, горизонтального переполнения нет.
- Повторный импорт и публикация идемпотентны. Основной и резервный каталоги revision 250 совпадают; payload сверены по SHA-256.
