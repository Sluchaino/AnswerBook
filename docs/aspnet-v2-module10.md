# ASP.NET Core — Проектирование HTTP API и REST

Десятый модуль добавлен по десяти файлам уроков, контрольному тесту и ключу. Оригиналы без изменений находятся в `server/theory-source/aspnet-core-v2-module10/`. Курс `aspnet-core-foundations-v2` v66, каталог revision 240.

Десять уроков содержат 20 мини-проверок, 50 итоговых вопросов уроков и 20 контрольных — всего 90 с пояснениями. Пять интерактивов размещены по одному в уроках 2, 3, 6, 8 и 10: HTTP-семантика, контракт повторов, сборка стабильной сортировки, исправление ETag-предусловия и проверка OpenAPI-контракта. Дополнительные уроки не создавались.

Доступны десять модулей из 27: 90 уроков, 50 интерактивов, 180 мини-проверок и 650 вопросов на оценку. Модули 11–27 показывают «Скоро появится». Первые девять модулей и их размещения упражнений сохранены; курс C# и его sidecar сверены по SHA-256. Источники и авторские ключи не отображаются в ученической теории.

## Исправление примера при импорте

В уроке 8 исправлены два недопустимых C#-выражения ETag: `$""v{version}""` заменено на `$"\"v{version}\""`. Значение заголовка содержит обязательные двойные кавычки, например `"v7"`. Исходный Markdown не менялся. Проверка сохранности code fences учитывает только эту коррекцию.

## Проверки

- 414 автоматических тестов и семь API-проверок проходят. Веб-сборка успешна. Lint содержит восемь прежних предупреждений; сборщик предупреждает о размере основного JS-файла.
- `scripts/check-aspnet-v2-module10.mjs`: 15 успешных SDK/HTTP-сценариев. Проверены ресурсы, создание и повторная замена PUT, DELETE 204→404, Accepted/Location и пустой 204, DTO без OwnerId, фильтрация/сортировка, 428/412/200 с увеличением ETag, параллельные версии API и OpenAPI 3.1 с 200/404.
- Клиентский фрагмент урока 3 проверяется с локальным тестовым сервером вместо example.org. Внешние запросы не отправляются. Это проверка синтаксиса и запроса, а не серверной реализации идемпотентных платежей.
- Оба допустимых порядка сборки сортировки компилируются и возвращают Id 4,1,2. Все четыре исправления ETag проверены: эталон отклоняет старые версии до мутации, неверные варианты либо отвергают актуальную версию, либо разрешают устаревшую запись.
- LINQ-фрагменты EF Core, PostgreSQL constraints, distributed Idempotency-Key storage и xUnit/WebApplicationFactory не выдаются за развёрнутые интеграции. Сохранены их необходимые контексты. Учебный ETag-handler не является полным RFC-парсером и не обеспечивает атомарность при параллельной записи; это ограничение явно указано в теории и задании.
- На ширине 390 px проверены правильные/неправильные решения пяти заданий, восстановление после перезагрузки и сброс рабочего ответа. Сброс сохраняет ранее полученную отметку успешного выполнения. Консоль без ошибок, горизонтального переполнения нет.
- Повторный импорт и публикация идемпотентны. Основной и резервный каталоги revision 240 совпадают; payload проверены по SHA-256.
