# Структура учебных курсов

Новые курсы используют `formatVersion: 2`:

```text
Курс
└── Модули
    └── Уроки
        ├── Часть теории
        ├── Короткий тест по прочитанному
        ├── Следующая часть теории / пример
        ├── Дополнительные короткие тесты при необходимости
        └── Итоговый тест урока
```

Модуль объединяет несколько уроков по одной большой теме. Внутри урока массив `blocks` задаёт точный порядок теории и коротких проверок. Можно чередовать их несколько раз. `finalTest` всегда располагается после всех частей урока; его задания должны отличаться от заданий коротких проверок.

## Формат данных

Готовый структурный шаблон: [course-template.json.example](course-template.json.example). Он не попадает в приложение или серверный каталог. Для настоящего курса скопируйте его в `server/course-source/<новый-id>.json`, замените названия, теорию и задания.

Поля курса:

| Поле | Назначение |
| --- | --- |
| `formatVersion` | Версия структуры, сейчас `2` |
| `id` | Постоянный уникальный ID курса; удалённые ID не переиспользуются |
| `version` | Версия содержимого; повышается при любом изменении опубликованного курса |
| `title`, `description` | Название и описание |
| `direction` | ID направления из `src/data/learning-directions.json` |
| `scope` | `dotnet` либо `universal` |
| `symbol`, `color`, `topicIds` | Оформление карточки и связь с каталогом открытых вопросов |
| `modules` | Массив модулей в порядке изучения |

У модуля есть `id`, `title`, необязательное `description` и массив `lessons`.

У урока есть `id`, `title`, массив `blocks` и обязательный `finalTest`. Урок начинается с теории и содержит хотя бы одну короткую проверку внутри. Один блок теории может содержать несколько абзацев, примеров кода или таблиц.

| Шаг | Поля |
| --- | --- |
| Теория | `id`, `kind: "theory"`, `title`, `content` |
| Проверка внутри урока | `id`, `kind: "test"`, `title`, `questions` |
| Итоговый тест урока | `id`, `title`, `questions` — отдельное поле `finalTest` |

Элемент `content` имеет `kind` (`paragraph`, `heading`, `code`, `table`) и непустой `text`. HTML не исполняется: теория и код выводятся как текст.

Задания `choice` содержат четыре различных варианта `options`, индекс правильного ответа `correct` от 0 до 3 и `explanation`. Задания `output` содержат допустимые текстовые ответы `answers` и `explanation`; для вопроса о коде добавляется `code`. Все задания имеют `id`, `kind`, `prompt`.

ID модулей уникальны в курсе; ID уроков и вопросов также уникальны во всём курсе. ID шагов и итогового теста уникальны внутри урока. ID модулей, уроков и шагов состоят из строчных латинских букв, цифр и дефисов. Сохраняйте ID неизменных материалов при обновлениях: по ним восстанавливается место прохождения.

## Прохождение и результат

- Пользователь выбирает модуль и урок в существующих кастомных списках; маленькие стрелки ведут между шагами, уроками и модулями. Списки прокручиваются с материалом, а компактная строка стрелок закрепляется у верхнего края под шапкой приложения.
- Теория показывается отдельным шагом. На проверках ответы проверяются кнопкой «Проверить ответ»; до проверки всех заданий стрелка вперёд недоступна. Неправильный ответ сопровождается объяснением, после проверки можно продолжать.
- После итогового теста урока открывается следующий урок. Последний тест последнего модуля завершает курс, если даны все ответы. Если пользователь пропускал уроки через списки, ему предлагается заполнить оставшиеся задания в общем тесте.
- Прогресс в процентах отражает долю отвеченных заданий: учитываются короткие проверки и итоговые тесты каждого урока, без двойного подсчёта. Чтение теории само по себе не добавляет процент к результату.
- Досрочная сдача содержит все задания обоих типов. Обратная связь в ней появляется после завершения, как и раньше.
- Сохраняются точный шаг, ответы, проверенные задания и результат курса. Работа над ошибками и условие награды от 80% применяются ко всем заданиям. Новых наград за отдельные уроки или модули нет.

## Публикация и совместимость

`npm.cmd run build` проверяет исходные курсы; `npm.cmd run content:publish` публикует их на сервер. Оба инструмента требуют новую структуру для новых файлов. Клиент проверяет и разворачивает вложенную структуру перед показом; внутренние плоские шаги служат только навигации и оценке, вручную задавать поле `lessons` на уровне курса не нужно.

Внешняя схема каталога сервера остаётся `schemaVersion: 1`; версия содержимого курса (`version`) и версия его структуры (`formatVersion`) — разные поля. Для нового формата потребуется обновить старое приложение один раз. После этого материалы такого формата можно получать с сервера и проходить из кеша офлайн.

Старые плоские сохранения и результаты поддерживаются для совместимости движка. Ранее удалённые курсы не возвращаются. Шаблон и тестовые данные не публикуются автоматически; в каталог добавлены девятнадцать новых модулей C#.

## Правила нового модуля C#

Курс может задавать `assessment: {practiceUngraded: true, bulkSubmission: true}`. Тогда мини-проверки не входят в точность, а итоговые тесты отправляются целиком. У модуля поддерживается отдельное поле `exam` с заданиями и необязательным рекомендуемым порогом `passPercent`. Вопрос `multi` содержит четыре `options` и массив правильных индексов `correct`: верен только весь набор без лишних вариантов. Подробнее: [модуль C#](csharp-module01.md).

В `blocks[]` поддержан тренировочный блок `exercise`: [формат, сохранения и примеры](interactive-exercises.md). Существующие theory/test не изменены.
# Количество уроков и интерактивов

Количество уроков определяется предоставленными файлами уроков. README, служебный ключ и контрольный тест не создают дополнительные уроки. На модуль нужно пять интерактивных заданий, не больше одного в уроке; уроки без интерактива допустимы. Фиксированного требования «пять уроков в модуле» нет.
